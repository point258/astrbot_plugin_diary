# 偷看孩子日记

她会写日记。你只能看到跟自己有关的那一段。

---

## 第一部分：这插件能干什么

### 先说人话

bot 平时在群里说话，说完就完了。这个插件让她**偷偷把这些事记下来**，晚上用第一人称写成一篇日记。

日记不是给你看的。但如果你跟她关系够好，她会给你一串密钥。你打开网页，输进去，就能看到**她那天写你的那几句**。看不到正文，也看不到别人的部分。

就这么个东西。

### 你能用到的东西

**1. 她会写日记**

每天晚上（默认 23 点后）写一篇，三四百字。不是流水账，是她自己视角的碎碎念：谁惹她了、谁给她端饭了、谁欠她的账没还。

她会翻旧账。之前骂过她的、请她吃过饭的、摸过她尾巴的，写的时候态度都不一样。因为插件会去读你的好感度，还有她记得的旧事。

**2. 你能看自己那一段**

好感度够高（默认超过 90），她会在聊天里给你一串密钥。

打开 `http://你的服务器:2588/`，粘进去，就能看到她写你的那两句话。密钥七天过期，用一次就记一次，随时可以作废。

别人拿到你的密钥也没用——那串只对应你那一篇里、你自己那一段。

**3. 你能管她的素材**

后台是 `http://你的服务器:2566/admin`，要密码。

里面能看到当天喂给她的每一条原始片段。写歪了她把谁写错了、漏了谁，你可以直接改；写得不满意，一键重写；不想留的，删掉。

也能手动补一条："今天其实还发生了这个"，她下次写的时候会算进去。

**4. 她偶尔会提一句**

只有一种情况：有人明确提到"日记""本子""密钥""密码"这些词。

那一轮会临时给她递一句话，让她知道"这会儿可以提日记"。其他时候，她完全不知道有这个插件存在。

不是每句话都插，也不写进人格。

### 装之前要知道的

**必须有的：**

- AstrBot 本体（这个不用说了）
- 两个能对外访问的端口：`2588`（给群友看）和 `2566`（你自己管）

**有没有都行的：**

- **self_learning**：装了，日记里她对每个人的态度会有冷暖差别。没装，所有人一视同仁，日记会平一点。
- **livingmemory**：装了，她能翻出"上次你说要请我吃饭"这种旧账。没装，只写当天的事。

这两个都是**只读**，不会往人家库里写东西，也不会改人家的配置。

**不需要装的：**

不用 pip 装任何东西。`aiohttp` 是 AstrBot 自带的。

### 怎么装

**方式一（推荐）**

插件管理页 → 上传安装 → 选 `astrbot_plugin_diary.zip` → 重启。

**方式二**

```bash
cd AstrBot/data/plugins
unzip astrbot_plugin_diary.zip
```

然后重启 AstrBot。

**第一次启动它会自己干这些事：**

- 建数据库
- 起两个面板
- 生成管理密码，打印在日志里
- 模型不用选，默认用你当前的对话模型

你唯一要做的是：在 `docker-compose.yml` 里把 `2588` 和 `2566` 映射出去。

### 用起来大概是这样

> 晚上十一点多，群里安静了。
>
> 她写了一篇：「今天又是被投喂的一天……那个谁端了七碗白米饭过来，还假装要抢回去，我尾巴都立起来了。嘴上说不要，其实全吃完了。」
>
> 第二天，你在群里问她："日记里是不是写我了？"
>
> 她说："好感度够了吗就看。"
>
> 然后私聊给你一串密钥。
>
> 你打开网页，看到的就是上面那段。

### 一些常见问题

**她一天没说话，会写吗？**

不会。素材少于 3 段就不写，硬写只会变成编故事。

**能不能只写我？**

不能。日记是她的，不是给你的服务。

**密钥能转发吗？**

能，但转发了别人就能看。作废在后台点一下就行。

**会不会影响她正常聊天？**

不会。除了关键词那一轮多几十个字，其他时候她看不到这个插件的任何东西。

## 第二部分：实现

### 1. 总体结构

```
astrbot_plugin_diary/
├── main.py       插件入口：钩子、调度、命令、生命周期
├── store.py      SQLite 存储层（WAL），所有表的读写
├── timeline.py   时间轴聚合：把零散对话拼成带时段的段落
├── writer.py     提示词构建、模型调用、JSON 解析与片段归一化
├── people.py     人物上下文：好感度 + 记忆检索（只读外部库）
├── panel.py      双站点 HTTP 面板（公开页 + 管理台）
└── persona.md    日记体人格模板
```

依赖方向是单向的：`main` 依赖其余模块，`panel` 只依赖 `store`，`people` 只读外部 SQLite。

### 2. 事件钩子与写入路径

插件挂两个钩子，都不修改 `ProviderRequest` 的正文内容：

**`@filter.on_llm_request`**

- 读取 `event.get_message_str()`、发送者、群号，写入内存中的 `_pending[umo]`
- 仅当文本命中关键词集合时，构造一个 `TextPart` 并 `mark_as_temp()` 后追加到
  `req.extra_user_content_parts`；该片段不进入对话历史，仅本轮可见
- 注入内容是**结论**而非分数（"这次可以给他看 / 别给"），并要求模型不得提及分数与门槛，
  避免模型自行推算阈值

**`@filter.after_message_sent`**

- 取出 `_pending`，从 `event.get_result().chain` 中提取 `Plain` 组件作为回复文本
- 过滤命令回执（`好感度系统状态`、`✅` 等前缀），避免污染素材
- 写入内存缓冲，每 5 秒或满 50 条批量落库，避免在消息链路里做同步 I/O

### 3. 数据模型

```sql
turns(id, group_id, user_id, user_name, trigger_text, reply_text, ts, is_at, day)
diaries(id, group_id, day, title, body, mood, intensity, model, created_at)
        -- UNIQUE(group_id, day)
fragments(id, diary_id, user_id, text)
view_keys(id, token_hash, fragment_id, user_id, group_id, created_at, expires_at, used_at)
```

`turns` 是素材，`diaries` 是成品，`fragments` 是"每人一段"的投影，`view_keys` 只存哈希。

同一天重写时先删除旧 `diaries` 行与其 `fragments`，再插入，避免 `INSERT OR REPLACE`
造成的孤儿片段。

### 4. 时间轴聚合

把素材按 `(day, segment)` 分组，同一组只输出一次标题：

```
2026.10.22中午
  point258：看看这个
  她：这谁画的冒牌鱼啊
```

时段划分：`00:00–04:59` 半夜（归属前一天）、`05–09` 早上、`09–12` 上午、
`12–14` 中午、`14–18` 下午、`18–24` 晚上。

跨天归属放在聚合层而不是写入层，是为了让"半夜"的叙事连续。

### 5. 生成流水线

一次生成包含两次模型调用：

**第一次：情绪判定**

输入是渲染后的时间轴与统计（段数、人数、被 @ 次数），输出严格 JSON：
`{mood, intensity, reason, tone}`。温度低、`max_tokens` 小，使用廉价模型。

**第二次：正文生成**

System prompt 为日记体人格；User prompt 依次拼接：时间轴、整体情绪、落笔时情绪、
`【你对他们已有的印象】`、写作约束、人物编号清单。

输出 JSON：`{"title","body","fragments":[{"i":1,"text":"..."}],"mood_tag"}`。

**片段对齐**

模型对 `user_id` 不可靠，因此提示词改用编号 `i`，并在解析层做四级回退：
`i` → `user_id` → 昵称反查 → 数量匹配时按顺序兜底。

**写作约束（节选）**

- 只挑 3–5 件事，不逐条复述
- 每件事后必须跟一句主观判断，只有事件没有观点的段落删除
- 允许跳跃，禁用"然后/后来/接着/结果"串联
- 不按人排队，同一个人可在不同段落出现
- 至少一段只写自己（体感、念头）
- 结尾停在具体事件上，不做总结

### 6. 人物上下文

`people.py` 只读两个外部库：

| 来源 | 取什么 | 用途 |
|---|---|---|
| `self_learning.user_affections` | `affection_level` | 映射为档位词，决定态度冷暖 |
| `livingmemory.memory_atoms` | `content` | 每人的旧事摘要，最多两条 |

记忆检索先按 `content LIKE %name%` 命中，再用 `entities LIKE` 补充；跨人重复的条目
只分配给第一个命中者，避免同一段群聊记忆被复制到所有人名下。

### 7. 密钥与访问控制

- 签发：`secrets.token_urlsafe(32)`，库中仅存 `sha256(token)`
- 绑定：`fragment_id`，因此一串密钥只能解锁一篇里的一个人
- 有效期：默认 7 天；校验时同时检查 `expires_at`
- 频控：同一 IP 每分钟最多 10 次，超出返回 429
- 失败响应统一为 404 文案，不区分"不存在"与"已过期"

### 8. 面板

两个独立的 `aiohttp` 站点，而非同一应用的不同路径：

| 端口 | 路由 | 鉴权 |
|---|---|---|
| 2588 | `/`、`/view`、`/v/{token}` | 无（凭密钥） |
| 2566 | `/admin*` | 会话 Cookie（12h） |

- 管理密码支持热更新：登录时通过 `password_provider` 实时读取配置，而非构造时快照
- 插件 `terminate()` 会调用 `AppRunner.cleanup()` 释放端口，避免热重载时
  `EADDRINUSE`
- 会话令牌保存在进程内存，重启即失效

### 9. 调度、幂等与失败处理

调度器每 600 秒轮询一次：`hour >= generate_hour` 且距上一篇日记的天数满足
`interval_days`，且当天素材段数 ≥ `min_segments`，才触发生成。

失败处理：

- 情绪判定失败 → 回落 `calm/0.3`，不阻断正文
- 正文解析失败 → 抛错并记录，不写半成品
- 面板端口被占用 → 记录错误并继续启动，不影响 bot 主体
- 外部库不存在 → 好感度按 0 处理，记忆为空

### 10. 性能与成本

- 消息路径：一次字典写入 + 周期性批量提交，无模型调用
- 生成路径：每天两次调用；实测繁忙日（99 段素材）约 **9.9k tokens**，
  其中正文输入 4.3k、输出 2.5k（含约 1.2k 思考 token）
- 面板：纯读 SQLite，与 bot 主循环隔离

### 11. 已知限制

- 只记录"她参与过的对话"，纯旁观的群聊不会进入素材
- 引用图片依赖 AstrBot 自身的引用解析与转述链路
- 管理台只有单一密码，无多账号与操作审计
- 素材保留期由使用者自行管理，插件不做自动清理
